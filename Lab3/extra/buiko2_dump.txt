[P41] 1.2 Вопросы заказчику и принятые решения
[P42] По превью: На макете интерфейса нет отдельного окна предпросмотра. Что должно отображаться в превью для аудио (.mp3, .wav) и офисных документов (.docx, .xlsx), у которых нет видеокадров? 
[P43] Решение: для видео генерировать миниатюру первого кадра, для остальных типов — отображать системную иконку типа файла. 
[P44] По лимиту времени: Каким образом рассчитать время работы до запуска обхода? 
[P45] Решение: поиск запускается штатно, но при достижении 60 минут непрерывной работы принудительно останавливается с выводом уведомления пользователю. 
[P46] По платформе: Обязательно ли ориентироваться на неподдерживаемые Delphi 7 и Windows XP/7? 
[P47] Решение: целевая платформа пересмотрена в пользу 64-битных ОС Windows 10 и Windows 11. 
[P48] По выбору путей: Как вводить несколько каталогов в однострочное поле? Будет ли кнопка проводника? 
[P49] Решение: добавлена кнопка «Обзор...» («Browse...») и возможность ручного перечисления каталогов через точку с запятой. 
[P50] По логированию: Что происходит при достижении логом 1 МБ?
[P51] Решение: настроена циклическая ротация логов: app.log переименовывается в app.log.1, запись продолжается в новый файл. 
[P52] По элементам управления: Каким образом штатно прервать длительный процесс сканирования? 
[P53] Решение: на форму добавлены кнопки «Пауза» и «Стоп». 

[P54] 2 Тест-план приложения «File Searcher»
[P55] 2.1 Суть и основные цели проекта
[P56] Суть проекта: Десктопное приложение «File Searcher» предназначено для автоматизированного рекурсивного сканирования файловой структуры заданных пользователем локальных директорий по маскам и категориям с последующей визуализацией метаданных и генерацией превью. 
[P57] Цели проекта: Предоставить пользователю инструмент поиска медиафайлов и документов с временем отклика UI  мс и гарантией безаварийной работы при любых ошибках доступа к файловой системе. 
[P58] 2.2 Требования, подвергаемые тестированию
[P59] В область тестирования включены критические функции: 
[P60] Выбор источников поиска: ввод абсолютного пути, выбор через диалоговое окно «Обзор...», валидация списка путей через разделитель ;, фильтрация пустых пробелов и пропуск некорректных путей. 
[P61] Фильтрация и категоризация: корректность поиска по группам «Аудио» (.mp3, .ogg, .wav, .mid), «Видео» (.avi, .mpg, .mpeg), «Офисные документы» (.doc, .docx, .xls, .xlsx) и по пользовательской маске (например, *.log). 
[P62] Управление сканированием: корректная работа фонового потока, реакция на нажатие кнопок «Старт», «Пауза», «Стоп», автоматическое прерывание при достижении тайм-аута в 60 минут. 
[P63] Визуализация результатов: заполнение таблицы (имя, путь, размер в читаемом формате, дата/время изменения), сортировка колонок, генерация кадра для видео и системных иконок для остальных типов. 
[P64] Строка состояния: отображение текущего анализируемого каталога в блоке «Сейчас проверяется» в реальном времени. 
[P65] Отказоустойчивость: корректная обработка отсутствия прав, битых файлов, циклических символических ссылок, ограничение глубины обхода (64 уровня). 
[P66] Журналирование: формат записей (метки времени, уровни INFO/WARNING/ERROR), своевременная ротация файла app.log при достижении 1024 КБ. 
[P67] Локализация: переключение языков (RU/EN) на лету без перезапуска, загрузка внешних языковых пакетов. 
[P69] 2.3 Требования, не подвергаемые тестированию
[P70] Вне области тестирования: 
[P71] Работа под Windows XP, Vista, Windows 7, 8: исключено, так как ОС сняты с поддержки; приложение оптимизировано исключительно под Windows 10/11 x64. 
[P72] Сканирование файловых систем UNIX (ext3, ext4, Btrfs, ZFS): исключено, так как Windows нативно не монтирует их без стороннего ПО. 
[P73] Сканирование сетевых хранилищ (SMB/NFS/WebDAV): исключено на первом этапе релиза; тестируется только локальная подсистема хранения. 
[P74] Воспроизведение медиафайлов из интерфейса: приложение является поисковиком, а не медиаплеером.
[P75] Стресс-тестирование сверхглубоких деревьев (> 64 уровней): требование программно ограничено на уровне спецификации (64 уровня рекурсии). 
[P76] 2.4 Тестовая стратегия
[P77] Тестирование проводится по многоуровневому подходу: 
[P78] Уровни тестирования:
[P79] Интеграционное тестирование: взаимодействие поискового движка (фоновый поток) с GUI и модулем логирования. 
[P80] Системное тестирование: сквозные сценарии от запуска программы до выгрузки результатов. 
[P81] Типы тестирования:
[P82] Функциональное: валидация масок, корректность парсинга расширений, ротация логов. 
[P83] Нефункциональное:
[P84] Тестирование производительности: замер скорости сканирования каталогов на SSD/HDD (не менее 500 элементов/сек на SSD). 
[P85] Тестирование отказоустойчивости: заблокированные файлы, папки без прав доступа, повреждённые видеозаписи. 
[P86] Тестирование удобства использования: читаемость таблицы, работа сортировок, отзывчивость интерфейса при активном поиске. 
[P87] Тестирование локализации: проверка отсутствия усечения текста, корректность подгрузки внешних конфигурационных файлов. 
[P88] Техники тест-дизайна: эквивалентное разделение, анализ граничных значений (глубина 0, 1, 63, 64, 65 папок; размер лога 1023 КБ, 1024 КБ, 1025 КБ), попарное тестирование для комбинаций категорий и типов директорий, предугадывание ошибок.
[P89] 2.5 Критерии качества
[P90]           Критерии начала тестирования:
[P91] Предоставлена стабильная сборка программы (.exe) и документация. 
[P92] Подготовлены тестовые наборы данных (директории с файлами нужных расширений, повреждёнными медиа и ограниченными правами).
[P93] Критерии приостановки и возобновления:
[P94] Приостановка: наличие блокирующего дефекта (падение программы при нажатии «Старт», недоступность GUI). 
[P95] Возобновление: исправлена блокирующей проблемы.
[P96] Критерии завершения тестирования:
[P97] 100% запланированных тест-кейсов.
[P98] Отсутствие открытых дефектов с приоритетом/критичностью.
[P99] Количество открытых дефектов уровня мелких ошибок не превышает 3.
[P100] Достигнуты целевые показатели производительности ( элементов/сек на SSD).
