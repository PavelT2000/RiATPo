[P33] 1. Цель работы и исходные данные
[P34] Цель лабораторной работы — устранение дефектов, логических противоречий и невыполнимых условий исходного технического задания к учебному проекту «File Searcher» (Вариант № 3), приведение требований к профессиональному инженерному стандарту в соответствии с ISO/IEC/IEEE 29148:2018 и рекомендациями базового курса С. Куликова.
[P35] Объект исследования: программное приложение «File Searcher» — десктопная утилита поиска и каталогизации файлов в среде операционных систем семейства Windows.
[P36] 2. Исходный текст технического задания (Вариант № 3)
[P37] 1. Приложение «File Searcher» (далее FS) предназначено для автоматического поиска файлов по заданному шаблону.
2. Приложение должно быть написано на Delphi 7 и работать под Win XP и Win 7.
3. Для поиска указывается начальный каталог или набор каталогов. FS автоматически сканирует каталоги на неограниченную глубину вложенности и отображает все найденные файлы в правой панели (см. скриншот 1).
4. Для поиска доступно три типа файлов (выбор производит вручную или с помощью комбо-бокса «Что искать»): Аудиофайлы (mp3, ogg, wav, mid); Видеофайлы (avi, mpg, mpeg); Офисные файлы (doc, docx, xls, xlsx).
5. По всем найденным файлам отображается: Имя; Полный путь; Размер; Дата-время создания файла; Скриншот с первым кадром.
6. Производительность: FS должно искать не менее 500 файлов в секунду при условии, что скорость чтения/записи на диск превышает 50 Мб в секунду. В случае, если общее время операции превышает 1 час, приложение не должно начинать работу.
7. Поддержка языков: Приложение должно поддерживать русский и английский языки по умолчанию. Должна быть возможность добавлять новые языки.
8. Логирование: FRS должно вести лог своей работы. Если размер лога превышает 1 Мб, ведение лога прекращается. Текущий анализируемый каталог должен отображаться в панели «Сейчас проверяется» внизу экрана.
9. Поддержка файловых систем: Должны поддерживаться все файловые системы Windows и UNIX. В случае обнаружения неподдерживаемой FS, FS должно аварийно завершать работу. Должна быть поддержка сети.

[P40] 3. Исправленное техническое задание (доработанные требования)
[P41] 3.1 Общие сведения и назначение
[P42] Приложение «File Searcher» (далее — FS) представляет собой настольную утилиту с графическим интерфейсом пользователя (GUI), предназначенную для автоматизированного поиска, фильтрации и предварительного просмотра мультимедийных и офисных файлов по заданным каталогам локальных накопителей и сетевых хранилищ.
[P43] 3.2 Целевая платформа и технологии реализации
[P44] • Приложение функционирует в среде 32- и 64-разрядных операционных систем Microsoft Windows XP (SP3), Windows 7 (SP1), Windows 10 и Windows 11.
[P45] • Программный код разрабатывается на Object Pascal (Borland Delphi 7 с обязательным использованием системного Win32 Unicode API либо совместимых средах Delphi XE+ / FreePascal Lazarus).
[P46] • Все операции обхода файловой системы обязаны использовать системные Unicode-вызовы (FindFirstFileW, FindNextFileW, GetFileAttributesW) для исключения искажения имен файлов с кириллицей, спецсимволами и иероглифами.
[P47] 3.3 Область поиска и правила обхода каталогов
[P48] 1. Пользователь может задать один или несколько каталогов для сканирования: прямым вводом путей через точку с запятой ';' в поле ввода, выбором папки в диалоге через кнопку «Обзор...», перетаскиванием папок (Drag-and-Drop) или указанием сетевых путей UNC (\\ServerName\ShareName\).
2. Приложение выполняет рекурсивный обход каталогов на глубину до 64 уровней (настраивается пользователем). Предусмотрен флаг отключения рекурсии («Искать только в указанном каталоге»).
3. Обход каталогов реализуется итеративно (очередь каталогов) в отдельном рабочем потоке, исключающем переполнение стека (Stack Overflow) и зависание интерфейса.
4. При обнаружении точек соединения (Junctions) и символических ссылок (Symlinks) приложение проверяет уникальный дескриптор тома и индекс файла (BY_HANDLE_FILE_INFORMATION). Повторный вход в посещенные узлы блокируется для защиты от зацикливания.
[P49] 3.4 Фильтрация и типы файлов
[P50] 1. Фильтрация файлов осуществляется выбором группы из списка «Что искать» либо вводом произвольной маски (например, *.pdf;*.txt;report*.*).
2. Предопределенные категории включают:
   - «Все файлы»: маска *.*;
   - «Аудиофайлы»: расширения .mp3, .ogg, .wav, .mid, .flac, .aac, .wma;
   - «Видеофайлы»: расширения .avi, .mpg, .mpeg, .mp4, .mkv, .wmv;
   - «Офисные файлы»: расширения .doc, .docx, .xls, .xlsx, .ppt, .pptx, .odt, .ods, .pdf, .txt, .rtf.
3. Сравнение расширений выполняется без учета регистра символов (.MP3 == .mp3).
[P51] 3.5 Отображение результатов и предпросмотр (Preview)
[P52] 1. Таблица результатов (TListView в режиме vsReport с OwnerData) содержит столбцы: порядковый номер (#), Превью (64 px), Имя файла, Полный путь, Размер (в Б, КБ, МБ, ГБ) и Дата изменения (Last Modified Time) в формате 'ДД.ММ.ГГГГ ЧЧ:ММ:СС'. Поддерживается сортировка по любому столбцу.
2. Логика генерации превью:
   - для видеофайлов — миниатюра первого ключевого кадра видеопотока (на 1-й секунде через DirectShow/VFW). При отсутствии кодека — иконка видео;
   - для аудиофайлов — извлечение обложки альбома из ID3v2 APIC (иначе значок ноты);
   - для офисных файлов — встроенная миниатюра документа либо системная пиктограмма формата.
3. Декодирование превью выполняется асинхронно в фоновом пуле потоков только для отображаемых на экране строк.
[P53] 3.6 Производительность и контроль длительности
[P54] 1. Скорость обхода файловой структуры — не менее 500 файлов в секунду на локальных дисках со скоростью чтения от 50 МБ/с.
2. Поиск стартует немедленно по нажатию кнопки «Искать» без предварительной блокировки.
3. Если поиск продолжается более 60 минут непрерывно, выводится диалоговое окно с подтверждением: «Поиск выполняется более 1 часа. Найдено файлов: N. Продолжить выполнение?» с кнопками «Продолжить» и «Остановить».
4. Пользователь может в любой момент остановить поиск кнопкой «Стоп» с мгновенным откликом GUI.
[P55] 3.7 Локализация интерфейса
[P56] Приложение поддерживает русский и английский языки интерфейса по умолчанию. Строки локализации хранятся во внешних файлах languages/ru.lng и languages/en.lng в кодировке UTF-8. Переключение языка выполняется через меню «Язык» на лету без перезапуска программы.
[P57] 3.8 Журналирование и строка состояния
[P58] 1. Журнал ведется в файле %LOCALAPPDATA%\FileSearcher\logs\FileSearcher.log в формате '[ГГГГ-ММ-ДД ЧЧ:ММ:СС] [УРОВЕНЬ] Сообщение'.
2. При превышении размера лога 1 МБ (1 048 576 байт) текущий файл переименовывается в FileSearcher.log.1, и запись продолжается в новый файл (ротация).
3. Текущий проверяемый каталог отображается в панели внизу экрана («Сейчас проверяется: [путь]»).
[P59] 3.9 Поддержка файловых систем, сети и надежность (Zero Crash)
[P60] 1. Поддерживаются все файловые системы, монтируемые ОС Windows: NTFS, FAT16, FAT32, exFAT, CDFS, UDF, а также сетевые ресурсы SMB (UNC-пути).
2. При сетевом таймауте (10 с) выводится предупреждение в лог, зависание приложения исключено.
3. Строгий запрет аварийного падения: при обнаружении неподдерживаемой ФС, RAW-раздела или при ошибке доступа (Win32 Error 5: Access Denied) приложение перехватывает исключение, делает запись в лог, пропускает объект и продолжает сканирование.
